## 1. 🔴 Car-type logo serving — ROOT CAUSE FOUND, FIXED

Your diagnosis pointed exactly at it. One root cause explains **both** symptoms:

The secure file-serving middleware has two folder lists: a *public* whitelist and a *private* (per-user) list. `CableCarTypes` was **missing from the public whitelist**, so requests fell into the private branch, which:
- requires an authenticated user → your anonymous `<img>` request → **401**;
- looks for the file under `CableCarTypes/{userId}/{file}` — but uploads are saved flat at `CableCarTypes/{file}` → **404** even with a valid token.

**The files were always written to disk correctly** — they were just served from the wrong branch. Your 5 test uploads (Toyota 25, BMW 26, Volvo 76, Genesis 70, Avatr 77) are intact on the server and will start serving the moment the fixed build is deployed — no re-upload needed (refresh them if you prefer).

**Fix:** `/CableCarTypes/` is now in the public whitelist — served anonymously like banners and station photos, exact same pipeline. Verified on dev: anonymous `GET /CableCarTypes/<file>.png` → **200 image/png** (was 401).

**Status:** fixed in the build, **needs the next deploy to reach prod** — we'll tell you the moment it's live so you can run the 62-logo bulk upload.

Also included in the same build (from your earlier recommendation): all image URLs are now built from the configured public base URL (`https://cable-app.com`), not the request host — the `localhost` class of bug can't recur, for car logos included.
